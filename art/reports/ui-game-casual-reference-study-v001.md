## 参考结论

### Papa's 系列：订单票据与多任务

- [Papa's Wingeria FAQ](https://i.flipline.com/games/papaswingeria/faq.html) 允许玩家把订单票据排列在 ticket line 上，并把当前票据放大阅读；其核心价值是“队列只保留摘要，当前订单单独放大”。
- [Papa's Mocharia To Go 开发复盘](https://www.flipline.com/blog/archives/19635) 明确记录：当订单票据左右顺序与制作台左右顺序不一致时，测试玩家会产生反向映射和困惑，开发者因此重做制作台。
- [Papa's Freezeria Deluxe Top Station](https://www.flipline.com/blog/archives/18292) 把大量配料拆成可切换托盘，而不是在同一屏铺开全部选项。

对本项目的应用：

1. 多订单最多显示 3 张紧凑票据，只展开当前订单。
2. 订单要求固定为“纸箱／包装／标签”三列。
3. 底部操作也严格保持“纸箱／包装／标签”同一左右顺序。
4. 三个类别标签始终可见，但一次只展开一个类别的选项架。

### Cooking Fever：计时与工作台

- [Cooking Fever Google Play 页面](https://play.google.com/store/apps/details?id=com.nordcurrent.canteenhd) 的官方截图展示了订单、顾客耐心和制作设备围绕工作台组织的时间管理结构。
- 本项目只吸收“计时贴着订单、工作台保持最大可操作面积”的原则，不使用其角色、餐厅、图标或具体布局。

对本项目的应用：

1. 删除占据视觉焦点的大圆倒计时。
2. 每张订单票据只保留细进度条；紧急订单仅把时间条变红。
3. 纸箱继续作为页面中央最大的可操作目标。

### Good Pizza, Great Pizza：一次一个任务焦点

- [Good Pizza, Great Pizza 官方 Press Kit](https://goodpizzagreatpizza.com/press/) 说明游戏在接单柜台与制作厨房之间切换；制作阶段把材料和制作台作为主要视觉焦点。
- 本项目不切换独立场景，但采用相同的“当前阶段只有一个主要焦点”原则。

对本项目的应用：

1. 当前订单详情只保留商品与三项包装要求。
2. HUD 删除常驻连击；连击改为结算或短暂动效，不持续占用顶部空间。
3. 选择工具时，只有当前类别的三个大选项出现。

## v004 页面结构

每个状态内部均为 750 × 1334：

| 区域 | 内容 | 设计目的 |
|---|---|---|
| 顶部 HUD | 目标、金币、投诉 | 只保留决策必需状态 |
| 订单票据轨道 | `01/02/03`、代表商品、时间细条 | 支持多订单但不展开多张详情 |
| 当前订单 | 大商品图、数量、纸箱/包装/标签要求 | 一秒读懂当前任务 |
| 传送带 | 4 个大商品 | 保持核心辨认操作 |
| 纸箱区 | 开箱与容量 | 页面最大操作目标 |
| 选项架 | 当前类别的 3 个选项 | 入口和选项不再隐藏 |
| 固定类别标签 | 纸箱、包装、标签 | 永远知道在哪里切换 |
| 主按钮 | 封箱发货 | 单一强主操作 |

## 三个状态

- A：单订单，纸箱标签激活，显示小/中/大纸箱。
- B：三订单队列，订单 `02` 激活，包装标签激活，显示气泡膜/冰袋/防水袋。
- C：三订单队列，订单 `03` 激活，标签页激活，显示易碎/冷藏/防水标签。

## 尚未决定

现有代码仍为逐单处理，并行订单属于新增玩法。实现前必须另外冻结：

- 同时存在 2 单还是最多 3 单，以及从第几关开始出现。
- 等待订单是否独立倒计时，超时后是否直接投诉。
- 切换订单时箱内商品和包装选择是否按订单分别保存。
- 从传送带拿取商品时归属当前订单，还是允许拖到指定订单。
- 提交当前订单后，剩余票据是否自动左移并切换。
